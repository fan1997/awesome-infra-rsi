# Contributing

Recommend a project when you can tell a reader what they will learn from it. We welcome a primary paper, an engineering report, a public benchmark, or an upstream implementation. A public description of a closed system can be useful if its evidence is accessible.

1. Choose the section for the project's main contribution. Update an existing entry when a project releases code or publishes a replication.
2. Describe the system change and its most informative result in one or two sentences. For a performance figure, include the workload, baseline, and measurement level (kernel, call site, or full service). For a benchmark, describe what the verifier measures.
3. Link directly to the evidence and identify the released component. A fork containing one patch and a full research framework offer different starting points for readers.
4. Update the matching English and Chinese entries when you can. If you write one language, a maintainer can help with the other.

Example submission in a pull request:

- **Project** and primary link
- **What changed** and who or what proposed the change
- **Evidence** including a paper section, measured comparison, or upstream PR
- **Code** and the part a reader can actually run

Figures in reading notes should carry a caption, a link to the original figure, and attribution. For third-party material, link to the original unless redistribution is permitted.
